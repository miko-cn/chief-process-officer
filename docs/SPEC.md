# Chief Process Officer — 产品规格书（SPEC）

> 状态：**草案 v0.2**（2026-08-15，待定项审阅后更新）
> 本文件是产品的唯一事实来源（single source of truth）。重大变更需更新本文件并在 [DISCUSSIONS.md](./DISCUSSIONS.md) 记录。

## 1. 产品定位

**一句话**：AI 驱动的 PC 性能管家 —— 主动性优化，而不是显示工具。

- 产品名：**CPO（Chip-Process-Optimizer）**（2026-08-15 定名）；仓库名沿用 chief-process-officer
- 核心差异化：**主动性**（启发式自动干预：何时介入、介入程度、何时恢复），对标 Process Lasso 的 ProBalance
- **启发式目标 = 响应性保护**（2026-08-16 会话⑲定案）：保持 OS 与前台程序的高响应性；降低 CPU 高挤占率是**手段**，不是硬性指标——系统还有 CPU 余量时绝不降级本来能跑的进程
- v1 **不含 AI**，但架构从第一天起面向 AI 扩展（见 §7）

## 2. 背景与动机

- Process Lasso：功能强大、ProBalance 启发式是行业标杆，但 UI/交互落后于时代，企业订阅贵
- System Informer（原 Process Hacker）：开源免费，但**只显示、需人工介入**，无启发式
- Windows 11 效率模式：微软官方在做"主动降优"，验证了需求真实，但粒度粗（前台/后台二分），无规则、无定制、无解释
- Process Tamer（2004）：停更前有人付费，"用户不愿手动管进程、希望工具自动判断"的需求存在二十年

**结论**：不做"另一个 Lasso"，做"新一代 PC 性能管家"。赢在：深度（规则化 + 可解释 + 自动化档案）+ 现代体验。

## 3. 目标用户

**全人群**（2026-08-15 修订）：凡认为电脑性能需要优化、希望提高系统响应度的用户，都是我们的用户——直接抢 Process Lasso 的用户盘。

- 不按人群细分（游戏 / 办公 / 开发者都是用户），按"卡顿场景"细分（编译、索引、容器、下载、AI/CLI 工具风暴等）
- 获客切入点仍走开发者社区（开发者是意见领袖、自带口碑传播），但产品定位不限于开发者
- 开发者用户的特点仍成立：能理解并信任自动判断；"引擎做了什么、为什么"对他们是功能不是负担

## 4. 产品铁律

1. **确定性引擎管执行，AI 管理解与建议**。策略引擎核心永远是确定性逻辑（阈值 + 状态机 + 参数），绝不把引擎包装成"AI"
2. **决策可解释、可预期**。**默认自动执行 + 全量留痕**（2026-08-15 会话⑫定案：逐条采纳太慢，用户不守 app；改为引擎自动干预 → 决策日志完整留痕 → 用户定期审阅 + 全局/按类开关）。信任建立靠"审阅面板 + 保守参数起步"，不是"逐条请示"
3. **遥测本地优先，默认不上云**。未来 AI 也仅上传"进程名 + 聚合统计"级脱敏快照，且用户主动触发
4. **遥测即一等公民**。所有数据为结构化、带时间戳的事件流；schema 文档化；本地 SQLite 存储
5. **每次干预留痕**。机器可读决策日志（做了什么、为什么、持续多久、效果如何）
6. **v1 不依赖内核驱动**（省签名成本 + 工作量；Job Object 限流覆盖 90% 价值）

## 5. 功能范围

### v1（MVP）
- 现代化进程视图：CPU/内存实时曲线，一眼看懂谁在吃资源（WinUI 3 / Fluent）
- **策略引擎**（Policy Engine）：优先级 / CPU 亲和性 / CPU 限流（Job Object）
  - 显式规则 = 最高优先级输入；启发式 = 默认决策函数，可调参
  - 二者是同一引擎的两个配置面，不是两套系统
  - **启发式触发条件**（会话⑲定案）：系统 CPU 饱和（无余量给 OS/前台）+ 进程是挤占者 + 非关键（非前台/非系统关键）三者同时成立才干预；系统有余量即不干预
  - **启发式三档保护**（会话⑳b/⑳c 定案）：前台进程本身（精确 PID）绝不干预；近期前台程序（1h 内曾为前台）温和降级（阈值 80% + 时长 10s）；**其余一切含前台子进程**（IDE 的 rg/编译等——降子进程不影响前台响应度，代价仅是变慢）按标准降级（50% / 30s）；**条件解除提前恢复**（目标进程 CPU 已不挤占 → 立即恢复，不等超时；规则干预除外）
- **默认自动执行**（2026-08-15 会话⑫定案）：引擎直接干预 + 每次留痕（做了什么/为什么/持续多久/恢复没）；**用户不做逐条审批**，改为定期打开 app 审阅操作日志 + **ProBalance 式全局开关**（会话⑫澄清：开关仅控制**干预执行**，关闭时遥测采集与决策日志照常、service 照常常驻）
- 决策日志 + 可视化回放面板（信任工具 + 营销素材）
- "为什么卡"一键诊断：卡顿前后负载快照 → 一句话结论 + 建议规则（v1 用本地模板生成，离线即时）
- 遥测采集与回放调参工具（内部开发用）
- **agent 数据接口（CLI / MCP）**：遥测查询与决策日志导出，供内部 agent 与未来 AI 层使用（v1 内置；用户侧的数据接口属付费功能）

### v1 明确不做
- LLM / 云服务 / 账号体系 / 网络权限
- 内核驱动
- 企业远程管理 / 策略下发
- AI 自然语言配置

### 未来（AI 扩展点，v1 只留接口）
- 诊断解释层：LLM 深度诊断（脱敏快照 + 用户主动触发，Pro 功能）
- 规则建议层：LLM 观察使用习惯 → 提议规则 → 用户确认（AI 只提议，不执行）
- 调参闭环：agent + 遥测回放自动寻参（内部杠杆，不面向用户）
- 场景档案：游戏模式/办公模式自动切换

## 6. 技术架构

**选型**：C# / .NET 8 + WinUI 3（讨论结论 2025-08-13；Rust 安全收益低、Windows UI 生态弱、agent 协作效率低，排除）

**系统支持**：Windows 10 1809+ 与 Windows 11（Windows App SDK 最低要求；2026-08-15 定案）。UI 单套 Fluent 样式——WinUI 3 控件 XAML 自绘制、不依赖系统主题，Win10/Win11 控件级一致；系统级差异（窗口圆角、Mica、标题栏、系统对话框、字体）用运行时版本检测 + 条件资源适配，Mica 等 Win11-only 特效在 Win10 降级。CI 矩阵覆盖 Win10 与 Win11。背景：微软 2026-06 将 Win10 免费安全更新延长至 2027-10，大量升不了 Win11 的老机器正是目标用户。

### 代码布局（agent 优先架构，工作日 agent 自主开发、周末人工审查）

```
chief-process-officer/
├─ app/        WinUI 3 壳层（薄，只做 UI；普通用户权限）
├─ service/    核心服务宿主（管理员权限，进程控制执行者）— M1 定稿：core + service 组合
├─ core/       纯 C# 逻辑：遥测模型、策略引擎、决策日志（零 UI / OS 依赖，xUnit 全覆盖）
├─ interop/    P/Invoke 隔离层：Process API、Job Object、ETW 事件订阅
├─ tests/      单元测试 + 遥测回放测试（录真实负载轨迹 → 断言决策正确）
└─ docs/       SPEC.md、DISCUSSIONS.md、ADR/
```

### 关键架构决策
- **进程模型**：GUI（普通用户）+ 引擎服务（管理员）分离（同 Lasso 架构；进程控制需提权，GUI 常年提权不现实）
- **分发**：**经典安装器（Inno Setup / WiX）**（2026-08-15 定案）；**不用 Microsoft Store**（沙箱限制管理员级进程控制，MSIX 对管理员服务有硬限制，详见 DISCUSSIONS 2026-08-15）
- **策略引擎数据流**：
  ```
  输入：进程遥测 + 系统状态(总负载/内存压力) + 前台状态 + 用户显式规则
    → 决策函数（纯逻辑，可单测）→ 输出：动作 + 理由 + 持续时间
    → 全部写入决策日志 + 遥测事件流
  ```
- **确定性屏障**：建议总线（ProposalBus）与执行路径（ExecutionPath）**物理分离**——AI 未来只走建议通道，代码结构强制隔离
- **GUI↔服务通信**：**gRPC over named pipes**（.NET 8 原生支持；2026-08-15 定案）。理由：纯本地不走网络栈（免疫防火墙 / 代理 / 本地 TUN 劫持）、自带 ACL 权限控制、低延迟流式推送遥测
- **前台检测归属**：**必须在用户会话内做**（接口限制：服务跑 Session 0，`GetForegroundWindow` / `SetWinEventHook` 均拿不到用户桌面前台）。方案：GUI 侧 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 事件驱动检测 → 经管道上报服务。GUI 最小化 / 退托盘**不影响**（进程仍在用户会话，hook 照常触发）；GUI 完全退出时启发式降级为"无前台信息"保守模式（不主动降后台进程，避免误伤）。普通权限即可，无需管理员。M2 增强：服务经 `WTSQueryUserToken` + `CreateProcessAsUser` 派生无头 helper 进程做检测，GUI 退出也不丢（2026-08-15 定案）
- **服务身份**：**M1 以 LocalSystem 运行**（能打开所有会话的进程，不牺牲功能）；安全收紧（最小 Token、管道 ACL）M2 做；GUI 始终普通用户权限。**杀毒误报对策**：只调用文档化 API（SetPriorityClass / SetProcessAffinityMask，与 Process Lasso / BES 同款行为，杀软一般认识）；发布版签名（Azure Trusted Signing）+ 经典安装器；不注入、不 hook 其他进程；误报走杀软厂商申诉流程（2026-08-15 定案）
- **服务生命周期（2026-08-15 会话⑭定案）**：service 以 **Windows 服务（LocalSystem，开机自启）** 形态常驻——M4 由安装器（Inno Setup）注册，与 App 开闭无关，引擎全天候工作。**App 启动时经 gRPC `GetStatus` 探测 service，未运行则经 SCM 拉起**（开发态先直接启动进程）；**App 支持最小化到托盘**（进程仍在用户会话，前台检测 hook 照常工作，见上）
- **gRPC 安全基线（2026-08-15 会话⑭定案、⑰落地）**：三层纵深——① 管道 ACL `CurrentUserOnly`（防其他用户）② 会话令牌 `AuthInterceptor`（防同用户任意进程）③ **门卫管道**：App 握手时 service 用 `GetNamedPipeClientProcessId` 校验对端进程必须是 Cpo.App.exe（存活 + 安装路径，发布版叠加 Authenticode 签名）→ 通过才发放**内存会话令牌**（256-bit，12h 有效，不落盘，service 重启即失效）。**文件令牌已废弃**（同用户可读，无法作为有效凭据）。安全级别到此为止——管理员级攻击（SeDebug 读内存/操控 service）在 Windows 信任边界内无解，明确不做
- **降优手段**：优先级 + CPU 亲和性硬降为主（直接操作进程句柄，无 Job Object 归属问题）；Job Object CPU 限流留作可选辅助。差异化场景：AI / CLI 密集工具风暴（grep、rg、编译器、模型工具等）在吃满 CPU 前动态降优、事后自动恢复（2026-08-15 定案）
- **降优必须可恢复**：每次干预记录原值（原优先级类 / 原亲和性掩码），条件解除、超时或引擎退出时**自动恢复原值**；恢复动作同样写入决策日志（2026-08-15 定案）
- **AI 扩展点接口**（v1 朴素实现占位，未来换实现不重构）：
  ```csharp
  interface IDiagnosticExplainer { string Explain(DiagnosticSnapshot s); }  // v1: 模板生成
  interface IRuleSuggester     { RuleSuggestion[] Suggest(UserProfile p); }  // v1: 空/静态模式
  class TuningHarness          { EvaluationResult Evaluate(PolicyParams p, ReplayData d); } // v1: 手动寻参
  ```

## 7. 遥测与决策日志（schema 草案，M1 定稿）

采样频率与保留策略：**配置化 + 可测试化 + 可用户配置**——默认值 + 配置文件 + 运行时调整；回放测试与线上走同一参数管线；企业可调（2026-08-15 定案）。

事件流（带时间戳，SQLite 本地存储）：
- `process.lifecycle`：进程启动/退出
- `sample.cpu` / `sample.memory`：周期采样（进程级 + 系统级）
- `ui.foreground`：前台窗口变化
- `policy.decision`：每次决策（输入快照 + 结论）
- `policy.action`：动作执行（目标、参数、结果、持续时长）
- `rule.changed`：用户/建议导致的规则变更

决策日志字段：触发条件、决策输入快照、动作、理由（人类可读 + 机器可读 JSON 双视图）、持续时长、最终效果。

**隐私红线**：数据默认本地；未来任何上传必须：脱敏（进程名 + 聚合统计，不含路径/窗口标题）＋ 用户主动点击触发。写进产品承诺。

## 9. 商业化

- **免费版**：进程监控 + 手动调整 + 预设的启发式规则（不含规则自进化、不含数据接口）——获客
- **Pro 买断** $19.9~29.9（对标 Lasso 个人版价位）：无限规则 + 规则自进化 + 场景档案 + 诊断报告
- **数据接口（企业 / 专业）**：遥测导出与评估接口（CLI / MCP），供企业评估与 agent 使用
- **企业版**（远期）：策略下发 + 远程管理，按年订阅
- 顺序：先个人市场验证付费意愿；个人用户被卡烦了会主动传播

## 11. 风险与对策

- **误伤信任**（启发式最大风险）→ 响应性导向的保守触发（会话⑲：系统饱和 + 挤占者 + 非关键三者齐备才干预）+ 决策日志 + 回放面板 + 全局开关；引擎错一次用户就关掉，v1 必须零误伤口碑
- **免费开源工具阴影** → 护城河 = UX + 自动化 + 可解释性 + 持续打磨（AI 调参闭环是迭代速度杠杆）
- **官方效率模式免费** → 差异化在深度：规则化 + 定制 + 解释性，官方永远只做"够用"
- **开发者对遥测/隐私敏感** → 本地优先写入产品承诺（铁律 3）
- **Windows-only 天花板** → 生态位养得起独立开发者（Bitsum 一个人 15 年），副业收入目标下合适
- **签名成本与 SmartScreen 信誉** → 低成本方案：Azure Trusted Signing（免硬件 token，约 $9.9/月）或国际便宜 OV 证书；EV 证书贵（2026 年国行 EV 约 ¥6888）仅作口碑起来后的升级；内测期自签名即可（详见 DISCUSSIONS 2026-08-15）

## 12. 开发协作模式（agent 优先）

- 周末：产品决策 + 代码抽查（不救火）
- 工作日白天：agent 自主开发（本会话的延续方式）
- **质量门禁：编译 + 单测强制**（本地 `dotnet build` + `dotnet test` 全绿才提交）；遥测回放测试是核心质量门禁
- **CI 触发策略（2026-08-15 定案）**：日常 push / PR **不触发** CI；仅**打 tag（`v*`）**或 GitHub Actions 页面**手动触发**时运行（编译 + 单测 + Win10/Win11 矩阵）。日常质量靠本地门禁，CI 是里程碑/发布节点兜底
